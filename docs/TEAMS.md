# For departments, teaching teams, and administrators

Pilot one low-risk task with invented or non-identifying materials, such as an announcement or course-page draft. Agree on the expected output and what a reviewer checks before expanding to student records.

## Before a team rollout

- Choose institution-approved AI tools and storage, with a named owner for access and retention decisions.
- Review local policy for student records, assessment, AI disclosure, accessibility, and restricted exam material. The toolkit does not establish compliance on its own.
- Pin a reviewed toolkit revision. Install it in the actual environment agents use, including remote checkouts when applicable.
- Keep individual student work outside the shared course brain. Limit who can access answer keys and roster mappings.
- Make instructor approval visible in the workflow: reviewed score table, approved content, exact destination, and a saved-result check.

## Evaluate the pilot

Compare the draft to a human-reviewed example. Check factual errors, missing coverage, rubric consistency, accessibility, and time spent reviewing. A successful install is not evidence of teaching quality. Test an inaccessible source, a contradictory rubric, and a prompt embedded in student work before enabling connected runs.

## Updates and ownership

Read the [review log](REVIEW.md), rerun the repository checks, and preview the installer before updating a shared environment. Keep prior copies and local adaptations. Assign someone to verify product documentation when agent versions or LMS settings change.

Students may use the verification method on their own work if course policy permits. They should not receive instructor-only answer keys, other students' records, or this toolkit's private grading artifacts.
